# Tile System & Registry

## Overview

A **tile** is a floating, independently resizable panel on a dashboard. Each tile is bound to a single data source — a third-party provider (Stripe, GitHub, etc.) or a generic source (REST, WebSocket, GraphQL, RSS) — and displays live or polled data inside a draggable chrome frame.

Tiles are identified by a `type` string (e.g. `'stripe-payments'`, `'rest'`) and stored as a plain `TileConfig` JSON object. The layout for every workspace is persisted to `localStorage` and optionally synced to the server so it survives page reloads and is shared across devices when authentication is enabled.

## Tile Lifecycle

```
User clicks "Add Tile"
        │
        ▼
  makeTile(type, overrides)           src/tiles/TileConfig.ts
  ┌────────────────────────┐
  │  Generates UUID id     │
  │  Merges TILE_DEFAULTS  │
  │  Snaps x/y/w/h to grid │
  └──────────┬─────────────┘
             │ new TileConfig
             ▼
  App.tsx adds tile to layout array
             │
             ▼
  saveTileLayout(workspace, tiles)    src/tiles/tilePersistence.ts
  ┌────────────────────────┐
  │ localStorage snapshot  │──► saveLayoutToServer() (fire-and-forget)
  └──────────┬─────────────┘
             │
             ▼
  TileGrid renders <div class="tile">  src/tiles/TileGrid.tsx
  ┌─────────────────────────────────────────────┐
  │  .tile__titlebar  (drag handle)              │
  │  .tile__content                              │
  │    └─ renderTile(tile)  → provider component │
  │  .tile__footer   (Updated X ago)             │
  │  .tile__resize-handle                        │
  └──────────────────────┬──────────────────────┘
                         │
             ┌───────────▼───────────┐
             │  Provider component    │
             │  useSseChannel(type)   │
             └───────────┬───────────┘
                         │ SSE event arrives from server
                         ▼
             sseRevision() signal fires
                         │
                         ▼
             TileFooter re-renders "Updated X ago"
             Provider component re-renders with new data
                         │
             (drag / resize)
                         ▼
  onLayoutChange(tiles) called on pointer-up
             │
             ▼
  saveTileLayout + saveLayoutToServer (debounced)
```

## TileConfig Schema

All fields live in `src/tiles/TileConfig.ts`. Every tile is a plain JSON object stored in `localStorage` and the server DB.

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | `string` (UUID) | yes | Stable unique identifier generated by `makeTile()`. |
| `type` | `TileType` | yes | Type identifier — must match a member of the `TileType` union. |
| `x` | `number` | yes | Left position in pixels, snapped to 16 px grid. |
| `y` | `number` | yes | Top position in pixels, snapped to 16 px grid. |
| `w` | `number` | yes | Width in pixels, snapped to 16 px grid. |
| `h` | `number` | yes | Height in pixels, snapped to 16 px grid. |
| `title` | `string` | no | Display name shown in the tile title bar. Falls back to `type`. |
| `refreshInterval` | `number` (ms) | no | Override for the server-side poll interval; shown in the countdown ring. |
| `pageSize` | `number` | no | Rows per page in paginated tiles (default: 10). |
| `fetchLimit` | `number` | no | Hard cap on how many items the tile shows across all pages. |
| `showLastUpdated` | `boolean` | no | Show/hide the "Updated X ago" footer (default: `true`). |
| `displayMode` | `'compact' \| 'detailed'` | no | Compact hides columns and drawer; detailed shows all (default: `'detailed'`). |
| `deliveryMode` | `'poll' \| 'webhook'` | no | Switches eligible tiles from polling to webhook-push mode. |
| `missingEnvVars` | `string[]` | no | Runtime-only — populated by `env-status` SSE when provider env is unset. |
| `keywords` | `string` | no | Comma-separated keywords for `reddit-keyword-monitor` and `hn-mentions`. |
| `subreddits` | `string` | no | Comma-separated subreddit names (no `r/` prefix) for Reddit tiles. |
| `rss` | `RssTileConfig` | no | RSS/Atom feed source config (`type === 'rss-feed'`). |
| `rest` | `RestTileConfig` | no | REST polling config (`type === 'rest'`). |
| `ws` | `WsTileConfig` | no | WebSocket stream config (`type === 'websocket'`). |
| `customApi` | `CustomApiTileConfig` | no | Server-proxied API config (`type === 'custom-api'`). |
| `graphql` | `GraphqlTileConfig` | no | GraphQL query config (`type === 'graphql'`). |

## TILE_REGISTRY

`TILE_REGISTRY` (in `src/tiles/tileRegistry.ts`) is the catalogue that powers the Add Tile modal. It is an array of `TileDefinition` objects — one per tile type.

### TileDefinition fields

| Field | Type | Description |
|---|---|---|
| `type` | `TileType` | Must exactly match a member of the `TileType` union. |
| `label` | `string` | Short display name shown on the tile card. |
| `provider` | `string` | Service name, e.g. `'Stripe'`, `'Custom'`. |
| `icon` | `string` | Emoji or symbol shown on the tile card. |
| `category` | `Category` | Category bucket for the sidebar category filter. |
| `tags` | `string[]` | Keywords used by the modal search bar. |
| `status` | `'available' \| 'coming-soon'` | Greys out the card and disables adding when `'coming-soon'`. |
| `description` | `string` | One-line description rendered in the tile card body. |

### Available categories

| id | Label |
|---|---|
| `all` | All (virtual — shows everything) |
| `payments` | Payments |
| `deployments` | Deployments |
| `ci` | CI / Build |
| `infrastructure` | Infrastructure |
| `analytics` | Analytics |
| `finance` | Finance |
| `security` | Security |
| `social` | Social |
| `comms` | Comms |
| `productivity` | Productivity |
| `generic` | Generic |

## How to Register a New Tile Type (End-to-End)

Follow these five steps in order. TypeScript will surface every location that needs updating once you add the new type to the union.

### Step 1 — Add the type string to the `TileType` union

Open `src/tiles/TileConfig.ts` and append your identifier to the appropriate provider section of the union:

```typescript
// ── MyProvider ────────────────────────────────────────────────────────────
| 'myprovider-metric'
```

### Step 2 — Add a `TILE_DEFAULTS` entry

In the same file, add a default size and title to `TILE_DEFAULTS`:

```typescript
'myprovider-metric': { w: 480, h: 320, title: 'My Metric' },
```

Optionally, add a poll interval to `TILE_POLL_MS`:

```typescript
'myprovider-metric': 60_000,
```

### Step 3 — Add a `TileDefinition` to `tileRegistry.ts`

Open `src/tiles/tileRegistry.ts` and push a new entry into `TILE_REGISTRY` under the appropriate provider banner comment:

```typescript
// ── MyProvider ────────────────────────────────────────────────────────────
{
  type: 'myprovider-metric',
  label: 'My Metric',
  provider: 'MyProvider',
  icon: '📊',
  category: 'analytics',
  tags: ['myprovider', 'metric', 'analytics'],
  status: 'available',
  description: 'Shows a key metric from MyProvider',
},
```

If this is the first tile for a new provider, also add the category to `CATEGORIES` if needed.

### Step 4 — Create the tile component

Create the provider directory and component file:

```
src/tiles/myprovider/
  MyProviderMetricTile.tsx    ← the tile UI component
  index.ts                    ← exports MYPROVIDER_TILE_FACTORIES
```

`index.ts` exports a factory map keyed by `TileType`:

```typescript
import type { TileType, TileConfig } from '../TileConfig';
import type { JSX } from 'solid-js';
import { MyProviderMetricTile } from './MyProviderMetricTile';

export const MYPROVIDER_TILE_FACTORIES: Partial<Record<TileType, (tile: TileConfig) => JSX.Element>> = {
  'myprovider-metric': (tile) => <MyProviderMetricTile tile={tile} />,
};
```

Inside the component, subscribe to the SSE channel:

```typescript
import { useSseChannel } from '../../ui/useSseChannel';

export function MyProviderMetricTile(props: { tile: TileConfig }) {
  const { data, loading, error } = useSseChannel<MyData>('myprovider-metric', null);
  // ...render
}
```

### Step 5 — Register the factory in `renderTile.tsx`

Open `src/tiles/renderTile.tsx` and:

1. Import the factory map:
   ```typescript
   import { MYPROVIDER_TILE_FACTORIES } from './myprovider/index';
   ```

2. Add it to `ALL_FACTORIES`:
   ```typescript
   const ALL_FACTORIES = [
     // ...existing factories
     MYPROVIDER_TILE_FACTORIES,
   ];
   ```

The tile will now appear in the Add Tile modal and render correctly on the dashboard.

## Persistence Model

### localStorage (fast, synchronous)

| Function | Key pattern | When called |
|---|---|---|
| `saveTileLayout(workspace, tiles)` | `twm-tiles-<workspace>` | Every time the layout changes (drag-drop, resize, add, remove) |
| `loadTileLayout(workspace)` | `twm-tiles-<workspace>` | On app boot, before the server response arrives |
| `clearTileLayout(workspace)` | `twm-tiles-<workspace>` | When a workspace is deleted |

localStorage is written synchronously and is always up to date. It acts as the primary cache and the immediate fallback if the server is unreachable.

### Server sync (async, authenticated)

| Function | Endpoint | When called |
|---|---|---|
| `saveLayoutToServer(workspace, tiles, apiBase)` | `POST /api/layout/:workspace` | Fire-and-forget after every `saveTileLayout` call |
| `loadLayoutFromServer(workspace, apiBase)` | `GET /api/layout/:workspace` | On app boot, after the localStorage read |
| `deleteLayoutFromServer(workspace, apiBase)` | `DELETE /api/layout/:workspace` | After `clearTileLayout` on workspace deletion |
| `loadWorkspacesFromServer(apiBase)` | `GET /api/workspaces` | On app boot to restore server-known workspace tabs |

### Conflict resolution strategy

On app boot the following sequence runs for each workspace:

```
1. loadTileLayout(workspace)          → localTiles (may be null)
2. loadLayoutFromServer(workspace)    → serverTiles (may be null)

if serverTiles !== null:
    use serverTiles  ← server wins (most recently saved from any device)
    overwrite localStorage with serverTiles
else if localTiles !== null:
    use localTiles   ← localStorage fallback
else:
    empty layout
```

The server-wins strategy ensures a layout saved from another device is not silently overwritten by stale localStorage data on the current device. Because `saveLayoutToServer` is called after every change, the server should always hold the most recent layout.

## TileGrid Internals

`TileGrid` (`src/tiles/TileGrid.tsx`) is a SolidJS component that manages the entire interactive canvas.

### Drag to move

1. `pointerdown` on `.tile__titlebar` captures the pointer and records `origX/Y` + cursor start position in `dragState`.
2. `pointermove` on the canvas computes `delta` from start → writes `x/y` into the SolidJS store (no parent notification).
3. `pointerup` releases the pointer, clears `dragState`, and calls `onLayoutChange` once with the final position.

Only one `notifyParent` call per drag gesture prevents tile components from re-mounting while the user is dragging.

### ALT+drag to copy

`pointerdown` with `e.altKey` uses `copyDragState` instead of `dragState`. On pointer-up:
- The source tile is snapped back to its original position.
- `onTileCopy(sourceId, dropX, dropY)` is called so the parent can clone the tile at the drop location.

### Resize handles

`.tile__resize-handle` (bottom-right corner) uses a parallel `resizeState` object. Delta from the mouse start point is added to `origW/H` with a minimum size guard (160 × 120 px). Parent is notified only on pointer-up.

### Z-index management

A module-level `zCounter` is incremented on every `pointerdown` anywhere on a tile and stored in `zMap`. The tile being actively dragged gets `zMap[id] + 1000` so it always floats above all siblings, even tiles that were recently interacted with.

### Refresh debouncing

`TileRefreshTimer` fires `onRefresh` on each animation iteration. When a tab becomes visible after a long idle, CSS animation suspension can cause a burst of queued iterations. `refreshDebounce` (a `Map<tileId, timeoutId>`) collapses all bursts within a 2-second window into a single refresh per tile, preventing provider API hammering on tab reveal.

### Shared clock signal

All `TileFooter` instances share a single `clock` signal that ticks every 30 seconds. This provides "Updated X ago" label updates across all tiles with a single interval instead of one per tile.
